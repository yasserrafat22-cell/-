# تجربة التطبيق على هاتف Android — دليل التشغيل

- الحالة: **معتمد**. سيرفر تجريبي على كمبيوتر داخل شبكة Wi-Fi المكتب فقط.
- البيانات: حساب مدير وبيانات تجريبية فقط. **لا تُدخل بيانات حقيقية.**

## ما تحتاجه

| على الكمبيوتر (Windows 10/11) | على الهاتف |
|---|---|
| Docker Desktop مثبت ويعمل | Android 7 أو أحدث |
| ملفات المشروع (تحميل ZIP من GitHub أو Git) | متصل بنفس شبكة Wi-Fi الكمبيوتر |

## الخطوة 1: تشغيل السيرفر على الكمبيوتر (أمر واحد)

1. ثبّت Docker Desktop من https://www.docker.com/products/docker-desktop/ ثم افتحه وانتظر حتى يكتمل تشغيله.
2. حمّل المشروع:
   - من GitHub افتح المستودع، واختر الفرع `claude/qadisiyah-analysis-planning-i2wgtx`.
   - اضغط **Code ← Download ZIP**، ثم فك الضغط.
3. افتح مجلد `deploy\trial`.
4. اضغط Shift + زر الفأرة الأيمن داخل المجلد، واختر **Open PowerShell window here**.
5. نفّذ الأمر:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start-trial.ps1
   ```

   - أول تشغيل يستغرق بضع دقائق لتحميل المكونات وبنائها.
   - في النهاية يظهر:

   ```
   Server address (type it in the app):  http://192.168.1.50:5080
   Username:                             admin
   Temporary password (first login):     xxxxxxxxxxxxxx7a
   ```

   **دوّن العنوان وكلمة المرور المؤقتة.**

**إذا لم يتصل الهاتف لاحقًا**، أعد تشغيل الأمر نفسه مرة واحدة من PowerShell **كمسؤول** (Run as Administrator). سيفتح المنفذ 5080 للشبكة المحلية فقط.

تأكد كذلك أن شبكة الـ Wi-Fi في Windows مضبوطة على **Private** وليست Public.

## الخطوة 2: تثبيت التطبيق على الهاتف

1. من صفحة GitHub Actions للتشغيل الأخير الناجح، حمّل `qadisiyah-debug-apk`. الرابط في التقرير المرفق.
2. فك الضغط وانقل `app-debug.apk` للهاتف (واتساب لنفسك، أو كابل، أو Google Drive).
3. افتحه على الهاتف، واسمح «بالتثبيت من مصادر غير معروفة» عند الطلب.

## الخطوة 3: تسجيل الدخول

1. افتح تطبيق «القادسية».
2. أسفل بطاقة الدخول اضغط الشارة البرتقالية **«نسخة تجريبية • السيرفر: …»**.
3. اكتب عنوان السيرفر من الخطوة 1، مثل `http://192.168.1.50:5080`.
4. اضغط **اختبار الاتصال**. يجب أن تظهر «السيرفر متصل». بعدها اضغط **حفظ**.
5. ادخل باسم `admin` وكلمة المرور المؤقتة.
6. تظهر **شاشة تغيير كلمة المرور**. اختر كلمة مرور جديدة: 8 أحرف على الأقل، فيها حروف وأرقام.
7. تظهر **الشاشة الرئيسية** بالبطاقات الخمس ✅

العنوان يُحفظ على الهاتف. إذا تغير عنوان الكمبيوتر يومًا ما، كرر الخطوات 2 إلى 4 فقط، دون الحاجة لتثبيت التطبيق من جديد.

## اختبارات إضافية مقترحة

| الاختبار | النتيجة المتوقعة |
|---|---|
| كلمة مرور خاطئة عند الدخول | «اسم المستخدم أو كلمة المرور غير صحيحة» |
| إغلاق التطبيق وفتحه | يدخل مباشرة للشاشة الرئيسية |
| إيقاف السيرفر ثم فتح التطبيق | يعمل مع شارة «تعمل دون اتصال بالسيرفر» |
| تسجيل الخروج | يعود لشاشة الدخول |
| الدخول بكلمة المرور المؤقتة بعد تغييرها | مرفوض |

## الإيقاف

```powershell
powershell -ExecutionPolicy Bypass -File .\stop-trial.ps1              # إيقاف مع الاحتفاظ بالبيانات
powershell -ExecutionPolicy Bypass -File .\stop-trial.ps1 -DeleteData  # حذف بيانات التجربة بالكامل
```

على Linux أو macOS: `./start-trial.sh` للتشغيل، و`docker compose down` للإيقاف.

## الأمان في هذا الإعداد

| المطلوب | كيف تحقق |
|---|---|
| بيئة معزولة | السيرفر وقاعدة البيانات داخل حاويات Docker على الكمبيوتر. قاعدة البيانات غير مكشوفة على الشبكة إطلاقًا |
| عدم النشر على الإنترنت | السيرفر يستمع على عنوان الكمبيوتر في الشبكة المحلية فقط. قاعدة الجدار الناري محصورة في «الشبكة المحلية + Private». لا يُفتح أي منفذ على الراوتر |
| HTTP مؤقتًا للتجربة فقط | مسموح في نسخة Debug وحدها، عبر إعداد أمان شبكة خاص بها. نسخة الإصدار تمنعه على مستويين: إعداد Android، وفحص داخل التطبيق يرفض أي عنوان غير HTTPS. كلاهما مغطى باختبارات |
| حماية كلمات المرور | كل الأسرار عشوائية في `.env`، وهو غير مرفوع ومقيد بصلاحيات المستخدم. كلمات المرور مخزنة كـ hash فقط |
| الصلاحيات وتغيير كلمة المرور الإجباري | كما هي دون أي تخفيف |

**حدود معروفة:** الاتصال داخل الشبكة المحلية غير مشفر. لذلك لا تُستخدم إلا بيانات تجريبية، ولا يُشغل على شبكة Wi-Fi عامة.

## لاحقًا (يحتاج موافقة منفصلة)

التجربة من خارج المكتب تتطلب HTTPS واستضافة أو Cloudflare Tunnel، مع بناء release موقع. لن يُنفذ أي منها دون موافقتك.
