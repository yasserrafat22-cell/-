# خطة تشغيل سيرفر تجريبي آمن

- الهدف: تسجيل الدخول من هاتف Android وتجربة شاشة تغيير كلمة المرور والشاشة الرئيسية.
- الحالة: **خطة جاهزة للتنفيذ بعد موافقتك**. لم يُنشر أي سيرفر.
- كل الملفات اللازمة موجودة في المستودع ويختبرها CI تلقائيًا (وظيفة `trial-server`).

## 1. الخيار الموصى به: سيرفر على جهاز داخل شبكة الشركة

يعمل السيرفر على كمبيوتر في المكتب، والهاتف يتصل به عبر نفس شبكة Wi-Fi.

**لماذا هذا الخيار للتجربة الأولى:**
- لا يحتاج شراء استضافة أو نطاق.
- لا يُكشف على الإنترنت إطلاقًا.
- يتوقف بأمر واحد.
- يُستخدم ببيانات تجريبية فقط.

### المتطلبات

| البند | التفاصيل |
|---|---|
| الجهاز | كمبيوتر Windows 10/11 أو Linux، ذاكرة 4GB أو أكثر، يبقى يعمل أثناء التجربة |
| البرامج | Docker Desktop (Windows) أو Docker Engine (Linux)، وGit |
| الشبكة | الهاتف والكمبيوتر على نفس شبكة Wi-Fi |
| عنوان ثابت | يُفضل حجز عنوان IP ثابت للكمبيوتر من الراوتر (مثال: `192.168.1.50`) |

### خطوات التشغيل (مرة واحدة)

```bash
git clone https://github.com/yasserrafat22-cell/-.git qadisiyah
cd qadisiyah
git checkout claude/qadisiyah-analysis-planning-i2wgtx
cd deploy/trial
./init-env.sh 192.168.1.50      # عنوان الكمبيوتر على الشبكة
docker compose up -d --build
curl http://192.168.1.50:5080/health    # يجب أن يظهر Healthy
```

ملاحظة: على Windows يُشغل `init-env.sh` من Git Bash.

- `init-env.sh` ينشئ ملف `.env` بأسرار عشوائية قوية: كلمة مرور قاعدة البيانات، ومفتاح توقيع الجلسات، وكلمة مرور المدير المؤقتة.
- يطبع كلمة مرور المدير المؤقتة مرة واحدة. **احفظها**.
- الملف محمي ولا يُرفع للمستودع.

### بناء APK موجه للسيرفر التجريبي

لا يحتاج أي أدوات على جهازك:

1. GitHub ← المستودع ← **Actions** ← **CI** ← **Run workflow**.
2. اختر الفرع `claude/qadisiyah-analysis-planning-i2wgtx`.
3. في الحقل `api_base_url` اكتب `http://192.168.1.50:5080`.
4. بعد اكتمال التشغيل حمّل `qadisiyah-debug-apk` من صفحة التشغيل.

### سيناريو التجربة على الهاتف

1. ثبت الـ APK (اسمح بالتثبيت من مصادر غير معروفة).
2. ادخل بـ `admin` وكلمة المرور المؤقتة ← تظهر **شاشة تغيير كلمة المرور** إجباريًا.
3. جرب كلمة مرور حالية خاطئة ← رسالة «كلمة المرور الحالية غير صحيحة».
4. اختر كلمة مرور جديدة تحقق الشروط ← تظهر **الشاشة الرئيسية**.
5. أغلق التطبيق وافتحه ← يدخل مباشرة (استعادة الجلسة).
6. أوقف السيرفر وافتح التطبيق ← يعمل مع شارة «تعمل دون اتصال بالسيرفر».
7. سجل خروج ← يعود لشاشة الدخول.

### الإيقاف والحذف

```bash
docker compose down        # إيقاف مع الاحتفاظ بالبيانات
docker compose down -v     # إيقاف وحذف قاعدة بيانات التجربة بالكامل
```

## 2. ضوابط الأمان في هذا الإعداد

| الضابط | التطبيق |
|---|---|
| لا أسرار في الكود | كل الأسرار مولدة عشوائيًا في `.env` (صلاحية 600)، ومستبعدة من Git |
| مفتاح الجلسات | السيرفر يرفض العمل بمفتاح التطوير خارج بيئة التطوير |
| قاعدة البيانات | غير مكشوفة على الشبكة؛ يصل إليها السيرفر فقط (يتحقق CI من ذلك) |
| حساب المدير | كلمة مرور مؤقتة يُجبر تغييرها عند أول دخول |
| السيرفر | يعمل بمستخدم غير root داخل الحاوية |
| الدخول | قفل بعد 5 محاولات خاطئة، وحد للطلبات لكل جهاز، وسجل تدقيق |
| الأجهزة | يمكن إلغاء أي هاتف فورًا من المدير |
| النطاق | يستمع على عنوان الشبكة المحلية المحدد فقط، ولا يُفتح على الراوتر |

### حدود معروفة (مقبولة للتجربة فقط)

- **الاتصال HTTP غير مشفر داخل الشبكة المحلية.** لذلك تُستخدم بيانات تجريبية فقط، ولا يُستخدم الإعداد على شبكة Wi-Fi عامة. نسخة التطوير من التطبيق هي وحدها التي تقبل HTTP.
- لا نسخ احتياطي آلي. بيانات التجربة قابلة للحذف.

## 3. للتجربة من خارج المكتب (يحتاج موافقة منفصلة)

إذا أردت التجربة عبر الإنترنت (مندوب في الميدان مثلًا)، يلزم **HTTPS إلزاميًا**. هناك خياران:

| الخيار | ما يلزم | التكلفة |
|---|---|---|
| أ. سيرفر سحابي صغير (VPS) + نطاق + Caddy (شهادة HTTPS تلقائية) | شراء VPS ونطاق | تقريبًا 5–10 دولار شهريًا + النطاق |
| ب. Cloudflare Tunnel من جهاز المكتب | حساب Cloudflare ونطاق | مجاني غالبًا + النطاق |

- في الحالتين يُبنى APK بنسخة release مع عنوان `https://...`.
- لا يُنفذ أي منهما دون موافقتك على الاستضافة والتكلفة، وفق قرار عدم النشر الإنتاجي.
