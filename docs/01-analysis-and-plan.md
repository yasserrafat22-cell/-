## 1. ملخص فهم المشروع

نظام CRM تجاري لشركة تتوسط بين **موردي** خامات البلاستيك (PVC / PP / HDPE / PET …) و**عملاء** (مصانع، محولون، تجار، موزعون). الجوهر: معرفة فورية بـ«من يحتاج خامة/Grade معينة» و«من يوفرها وبأي سعر وتاريخ»، ومتابعة العميل والمورد حتى يتحول الاحتياج إلى طلب مؤكد ثم تعامل مكتمل.

الثوابت المعتمدة:

- الهوية: الشعار الأصلي، الأزرق والأخضر والأبيض، بطاقات بحواف سفلية ملونة، موجات علوية وسفلية، واجهة عربية RTL.
- الرئيسية: خمس بطاقات (ص4).
- تسجيل سريع بأقل الحقول، واستكمال لاحق.
- آخر طلب وآخر تواصل وحالة العميل/المورد **مشتقة** من الأحداث وبقواعد قابلة للضبط، لا يُدخلها المستخدم.
- سجل أسعار تاريخي لا يُحذف؛ السعر لا يعني توفر مخزون.
- البحث الذكي أولوية قصوى، والمطابقة على مستوى الخامة + Grade + الوحدة مع تمييز «مؤكدة» عن «محتملة».
- التقارير: واجهة تفاعلية داخل التطبيق، وقالب A4 رسمي للطباعة/PDF فقط، وExcel بيانات منظمة.
- الصلاحيات تُطبق في السيرفر، لا كلمات مرور مكشوفة، سجل تدقيق.
- كل الأسماء والأرقام والنسب في الصور أمثلة توضيحية.

### 3.3 إجابات الأسئلة المفتوحة

1. المندوب يرى ما تسمح به صلاحياته ويعدّل سجلاته فقط؛ الأسعار الحساسة والأرباح بصلاحيات منفصلة.
2. الشركة الواحدة يمكن أن تكون عميلًا وموردًا دون تكرار هويتها ← جدول `parties` موحد بأدوار.
3. استعادة كلمة المرور من مدير النظام مع إجبار تغييرها بعد إعادة التعيين.
4. OpenStreetMap مبدئيًا، خلف واجهة خدمة خرائط قابلة للاستبدال.
5. الوحدة الأساسية كيلوجرام؛ طن = 1000 كجم؛ الشيكارة والأوزان المخصصة تُعرّف من الإعدادات.
6. قواعد التصنيف قابلة للتعديل، بالقيم المقترحة مبدئيًا، مع حالة «عميل جديد» عند نقص البيانات.
7. بيئة تطوير واختبار محلية فقط؛ لا استضافة ولا نشر إنتاجي.
8. لا افتراض لعدد المستخدمين أو حجم البيانات؛ التصميم للتوسع والاختبار بأحجام واقعية.
9. الشعار الأصلي PNG تم توفيره ويُستخدم كما هو.
10. خط Cairo مبدئيًا.

قيم التصنيف الافتراضية (قابلة للضبط):

- **جديد**: لا توجد طلبات مؤكدة بعد، أو عمر السجل أقل من 30 يومًا.
- **نشط**: طلب مؤكد خلال آخر 60 يومًا.
- **يحتاج متابعة**: متابعة مستحقة، أو تأخر عن متوسط دورة الشراء بأكثر من 1.5×.
- **متوقف**: لا طلبات منذ 120 يومًا.
- التصنيفات حصرية بترتيب أولوية ثابت.

## 4. المعمارية التقنية

```
┌──────── Flutter App (Android أولًا، ثم Desktop/Web للاب) ────────┐
│ Presentation : Widgets + go_router + Riverpod — Responsive         │
│ Application  : Use cases / services                                │
│ Domain       : Entities + قواعد العمل (الحالة، المطابقة، التحويل)  │
│ Data         : Repositories → Local (drift/SQLite مشفرة) + Remote  │
│ Sync Engine  : Outbox + Pull cursor + Conflicts + Retry/backoff    │
└──────────────────────────── HTTPS / JWT ──────────────────────────┘
┌──────── ASP.NET Core Web API (LTS) ────────┐
│ Auth: hashing + JWT + refresh rotation      │
│ Policy-based RBAC + حجب الحقول حسب الصلاحية │
│ Modules: Parties, Catalog, Orders, Supplies,│
│  Interactions, Prices, Opportunities,       │
│  Search, Reports, Import, Sync, Audit, Files│
│ Excel: ClosedXML (MIT)                      │
└───────────────────┬────────────────────────┘
      PostgreSQL (pg_trgm, unaccent) + تخزين ملفات
```

- **PDF**: مكتبة Dart `pdf` + `printing` (رخصة Apache-2.0، تدعم العربية RTL وتكرار رؤوس الجداول والروابط). البيانات تأتي من الـ API بعد تطبيق الصلاحيات، وكل تصدير يُسجل في التدقيق. تم استبعاد QuestPDF بسبب ترخيصها التجاري.
- **Monolith معياري** مناسب لحجم الشركة.
- **اللاب لاحقًا**: نفس الكود بثلاث نقاط عرض (موبايل < 600، تابلت، لاب ≥ 1200) دون تغيير الـ API.

## 5. مخطط قاعدة البيانات

أعمدة مشتركة لكل جدول قابل للمزامنة: `id UUIDv7` (يولده العميل)، `created_at/by`، `updated_at/by`، `row_version BIGINT`، `deleted_at`، `origin_device_id`.

**الهوية والصلاحيات**: `users` (hash لكلمة المرور، `must_change_password`)، `roles`، `permissions`، `role_permissions`، `user_roles`، `devices` (قابلة للإلغاء)، `refresh_tokens`، `representatives` (مرتبط اختياريًا بـ `user_id`).

**البيانات الأساسية**: `countries`، `governorates`، `regions`، `activity_types (applies_to)`، `units (code, base_unit_id, factor_to_base)`، `currencies`، `exchange_rates (rate, effective_date)`، `lookup_values (category, code, name_ar, name_en, semantic_kind, sort, is_active, is_system)`، `settings`.

**الكتالوج والمطابقة**: `materials`، `material_aliases (alias, normalized, kind)`، `grades (material_id, code, specs JSONB)`، `grade_equivalences (grade_a, grade_b, level, approved_by)` — التوافق الفني يُعتمد يدويًا ولا يُستنتج من الأسماء.

**الأطراف**: `parties` (الاسم، الاسم المطبّع، `is_customer`، `is_supplier`، النشاط، المندوب)، `party_phones (e164, is_whatsapp, whatsapp_e164)`، `party_addresses (country, governorate, region, line, lat, lng)`، `customer_interests`، `supplier_products`، `attachments`.

**المعاملات**: `price_quotes` (إضافة فقط)، `orders` + `order_lines` + `order_stage_history`، `supplies` + `supply_lines`، `interactions`، `follow_ups`، `opportunities`، `notifications`.

**المشتقات**: `party_stats` — يُحدّث في السيرفر داخل نفس المعاملة.

**الاستيراد والتدقيق والمزامنة**: `import_batches (file_sha256, mapping, status, summary)`، `import_rows`، `audit_log`، `sync_ops (client_op_id UNIQUE)`.

## 6. البحث الذكي والمطابقة

1. **التطبيع**: توحيد أ/إ/آ←ا، ة←ه، ى←ي، إزالة التشكيل والتطويل، الأرقام العربية←لاتينية، حالة صغيرة، توحيد فواصل الـ Grade (SG-5 = SG5 = sg 5)، الهواتف E.164.
2. **كشف نوع الاستعلام**: هاتف ← Grade ← خامة/اسم بديل ← اسم طرف.
3. **الاقتراحات أثناء الكتابة**: `pg_trgm` + `unaccent` في السيرفر، وFTS5 محليًا دون اتصال.
4. **النتائج**:
   - خامة/Grade: عملاء (مشترٍ سابق / مستفسر فقط / مهتم) + موردون مع آخر سعر وتاريخه ووسم انتهاء الصلاحية.
   - مورد: منتجاته ← العملاء المرتبطون (اشتروا / استفسروا فقط).
   - عميل: احتياجاته وسجله ← الموردون المطابقون.
5. **مستويات المطابقة**:

| المستوى | الشرط |
|---|---|
| ✅ مؤكدة | نفس الخامة ونفس الـ Grade أو Grade مكافئ معتمد |
| 🟡 محتملة | Grade غير محدد لدى أحد الطرفين، أو بديل يحتاج مراجعة، أو وحدات غير قابلة للتحويل |
| ⛔ غير مطابق | لا يُعرض كمطابقة |

لا توحي النتيجة بتوفر المنتج. لا تُطابق PP مع PPR ولا HDPE مع LDPE إلا بعلاقة معتمدة.

## 7. العمل دون إنترنت والمزامنة

| دون اتصال | يحتاج اتصال |
|---|---|
| تسجيل/تعديل العملاء والموردين، التواصل، الطلبات، التوريدات، الفرص | أول دخول على الجهاز، تغيير كلمة المرور |
| البحث المحلي وعرض الملفات المخزنة | إدارة المستخدمين والصلاحيات والأجهزة |
| تحديد الموقع، إرفاق الداتا شيت (رفع مؤجل) | تعديل البيانات الأساسية، استيراد Excel |
| الأسعار المخزنة لمن له صلاحية (مشفرة) | الأرباح، PDF/Excel الرسمي |

- **Push**: Outbox محلي بـ `client_op_id`، دفعات، إعادة محاولة بتأخير متزايد، السيرفر idempotent.
- **Pull**: حسب `row_version` cursor، مع حجب الحقول غير المصرح بها.
- **التعارضات**: السجلات الإضافية بلا تعارض؛ القابلة للتعديل ترسل `base_version` — دمج تلقائي للحقول المختلفة، و409 + شاشة حل تعارض لنفس الحقل. لا تعارضات صامتة.
- **التكرار**: فحص فوري عند الاتصال؛ ودون اتصال يُعلّم كـ«مكرر محتمل» للمراجعة اليدوية.
- **الجلسة**: refresh token محدود المدة، قفل محلي، إلغاء الجهاز من السيرفر يمسح البيانات المحلية عند الاتصال التالي.
