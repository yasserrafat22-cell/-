## 1. التحديث التراكمي (الأولوية)

| المتطلب | التنفيذ | الاختبار |
|---|---|---|
| الحفاظ على قاعدة البيانات | ترحيل `Phase3CoreData` إضافي فقط (18 جدولًا جديدًا)؛ لا حذف/إعادة تسمية/تعديل | `MigrationSafetyTests` يفشل لو ظهر Drop/Rename/Alter/Sql؛ `SchemaUpgradeTests` يرقّي قاعدة بإصدار المرحلة 2 |
| عدم إعادة إنشاء admin أو فرض تغيير كلمة المرور | المدير يُنشأ فقط إذا لا يوجد أي مستخدم؛ القوائم الأساسية تُضاف الناقص منها فقط ولا تُستبدل تعديلاتك | `SchemaUpgradeTests` (تشغيل مرتين بكلمة مرور bootstrap مختلفة) + اختبار الترقية الحقيقي |
| `.env` وكلمات المرور والمفاتيح | لا يوجد سكربت يكتب على `.env` القائم؛ `start-trial.sh` لا يغيّر العنوان إلا إذا مررته صراحة | اختبار الترقية يقارن بصمة `.env` قبل وبعد |
| منع حذف قاعدة البيانات | لا يوجد `down -v` في أي سكربت؛ حُذف خيار `-DeleteData` من `stop-trial.ps1` | فحص CI يفشل لو ظهر `down -v` أو `volume rm` في `deploy/` |
| نسخ احتياطي واستعادة | `backup-trial.sh` (مع تحقق من صلاحية الملف)، `restore-trial.sh` (تأكيد + نسخة من الوضع الحالي أولًا)، و`update-trial.sh` يأخذ نسخة إلزامية | داخل اختبار الترقية |
| APK فوق القديم | Application ID ثابت، مفتاح توقيع تجريبي ثابت في المستودع (للـ debug فقط)، Version Code يزيد مع كل بناء | محاكي Android: تثبيت النسخة السابقة ← كتابة بيانات ← `adb install -r` الجديدة ← البيانات باقية و `firstInstallTime` لم يتغير |
| `init-env.sh` | المصدر مُصلح (بدون `openssl`، يرفض الكتابة فوق `.env`)؛ نسختك المحلية تُحفظ في `backups/` | داخل اختبار الترقية |

**اختبار الترقية الحقيقي في CI** (`.github/scripts/upgrade-server-test.sh`): يشغّل الإصدار المثبت عندك
(`ff9087b`) بـ Docker، يغيّر كلمة مرور admin، يعدّل `init-env.sh` محليًا، ثم ينفّذ خطوات الدليل حرفيًا ويتحقق من:
بقاء hash كلمة المرور و security stamp، عدم عودة إجبار التغيير، رفض كلمة المرور المؤقتة القديمة، صلاحية جلسة الهاتف
(refresh token)، عدم إعادة إنشاء الـ volume، ثبات `.env`، وجود النسخة الاحتياطية، عمل واجهات المرحلة 3؛ ثم تحديث
ثانٍ بالسكربت مباشرة دون أي أثر على البيانات.

## 2. السيرفر

- جداول جديدة: القوائم (أنواع النشاط، نتائج التواصل، المحافظات، العملات)، الوحدات، الخامات وأسماؤها البديلة والدرجات،
  المندوبين، الإعدادات، الأطراف (عميل/مورد/الاثنان) وهواتفها، اهتمامات العميل، منتجات المورد، عروض الأسعار (إضافة فقط)،
  التواصل، الطلبات وبنودها وسجل مراحلها، التوريدات وبنودها.
- واجهات `/api/v1`: `reference`، `admin/materials`، `parties` (إنشاء/عرض/تعديل/قائمة/إضافة دور/منتجات)،
  `supplier-products/{id}/quotes`، `parties/{id}/interactions`، `orders` (+ `stage`، `hold`)، `supplies` (+ `status`)، و`version`.
- قواعد: منع تكرار رقم الهاتف (يعرض الطرف الموجود مع خيار إضافته كعميل/مورد)، الأرقام بصيغة دولية، معرفات من التطبيق
  (إعادة الإرسال لا تكرر السجل)، تعارض التعديل المتزامن برسالة واضحة، انتقالات مراحل الطلب المسموحة فقط، حساب الحالة
  (جديد/نشط/يحتاج متابعة/متوقف) من آخر تعامل وإعداداته، وكل تعديل مسجل في سجل التدقيق.
- الصلاحيات: المندوب يرى ويعدّل عملاءه، المدير الكل؛ الأسعار خلف صلاحيات منفصلة.

## 3. التطبيق (مطابق لتصميمات ص8 وص9)

- إضافة عميل/مورد سريعًا، بيانات العميل/المورد (نظرة عامة، الطلبات/التوريدات، التواصل، التفاصيل)، تسجيل طلب/توريد
  بعدة خامات ووحدات، تسجيل تواصل بنتيجته وموعد المتابعة، استكمال البيانات. منتجات المورد وآخر أسعاره تظهر داخل تبويب
  «التفاصيل» حتى تبقى التبويبات الأربعة كما في التصميم.
- الاتصال وواتساب يفتحان التطبيق المناسب ثم شاشة تسجيل النتيجة.
- عميل API موحد: تجديد الجلسة مرة واحدة تلقائيًا، رسائل الأخطاء بالعربية، وإنهاء الجلسة إذا أُلغي الجهاز.
- مفاتيح التخزين الآمن على الهاتف ثابتة ومقفلة باختبار، حتى لا يضيع عنوان السيرفر أو الجلسة بعد التحديث.

## 5. يحتاج موافقتك

1. **شاشتا قائمة العملاء والموردين** — لا يوجد تصميم معتمد؛ المقترح في `docs/phase3/proposals/`
   (بحث، فلاتر الحالة، بطاقة لكل طرف مع اتصال/واتساب، زر إضافة). غير مربوطتين بالتطبيق حتى توافق.
   حاليًا بطاقتا «العملاء» و«الموردين» في الرئيسية تفتحان الإضافة السريعة.
2. شاشات إدخال عروض الأسعار وملفات المواصفات — بلا تصميم معتمد؛ واجهات السيرفر جاهزة، والواجهة تُقترح لاحقًا.
3. اختيار الموقع على الخريطة مؤجل (حقل العنوان النصي متاح).

## 6. ملاحظات

- **مرة واحدة فقط:** APK الموجود على هاتفك موقّع بمفتاح مؤقت قديم، فيلزم حذفه وتثبيت الجديد هذه المرة؛
  السيرفر وبياناته وكلمة المرور لا تتأثر. كل تحديث بعده يُثبّت فوق السابق.
- أرسل لي نسختك المعدلة من `init-env.sh` (تُحفظ في `backups/init-env.sh.local`) لأتأكد أن إصلاحك مشمول في المصدر.
- المستودع عام (public)؛ لا تُرفع أي أسرار، و`.env` و`backups/` مستبعدان من git. مفتاح التوقيع المرفوع للتجربة (debug) فقط.
