# تقرير المرحلة 2 — الأساس التقني

- التاريخ: 2026-10-27
- الفرع: `claude/qadisiyah-analysis-planning-i2wgtx`
- الحالة: **بانتظار المراجعة البصرية للشاشتين قبل التوسع لباقي الشاشات**

## 1. ما تم تنفيذه

### البنية والبيئة

- مستودع واحد: `app/` (Flutter)، `server/` (.NET)، `docs/`.
- `docker-compose.yml` لقاعدة PostgreSQL المحلية.
- CI في `.github/workflows/ci.yml`: اختبار السيرفر على PostgreSQL، تحليل واختبار التطبيق، بناء APK تجريبي.
- المراجع الأصلية محفوظة في `docs/reference/` دون تعديل، ومنها الشعار الأصلي PNG.

### التطبيق (Flutter 3.47.7)

- نظام الهوية: ألوان الشعار، خط Cairo، الموجات العلوية والسفلية، البطاقات، الحقول، الزر المتدرج.
- واجهة عربية RTL كاملة، وتصميم متجاوب (390×844 مرجعًا، مع اختبار 360×640 و800×1280).
- **شاشة تسجيل الدخول** (ص5): اسم المستخدم، كلمة المرور، إظهار/إخفاء، رسائل أخطاء عربية، «نسيت كلمة المرور؟» يشرح مسار الاستعادة عبر المدير (قرار السؤال 3).
- **الشاشة الرئيسية** (ص4): البطاقات الخمس، مع زر تسجيل خروج ومؤشر «تعمل دون اتصال».
- استعادة الجلسة عند فتح التطبيق؛ إن تعذر الوصول للسيرفر تُستعاد الجلسة دون اتصال حتى انتهاء صلاحية رمز التحديث.
- الرموز تُحفظ في التخزين الآمن (Android Keystore)، ومعرف ثابت لكل جهاز.
- إعدادات Android: اسم التطبيق «القادسية»، أيقونة من الشعار الأصلي، HTTP مسموح في نسخة التطوير فقط، توقيع الإصدار من `key.properties` غير المرفوع.

### السيرفر (.NET 10 LTS + PostgreSQL 16)

- طبقات: Domain / Application / Infrastructure / Api.
- جداول: `users`، `roles`، `user_roles`، `role_permissions`، `devices`، `refresh_tokens`، `audit_log` (ترحيل `InitialIdentity`).
- الأدوار الأربعة المعتمدة مع 21 صلاحية تفصيلية؛ الصلاحيات تُفرض على السيرفر في كل طلب.
- كلمات المرور: PBKDF2-HMAC-SHA512 (خوارزمية ASP.NET Core Identity)، سياسة: 8 أحرف على الأقل مع حروف وأرقام.
- قفل الحساب بعد 5 محاولات خاطئة لمدة 15 دقيقة، وحد لعدد طلبات الدخول لكل IP.
- رمز دخول قصير (15 دقيقة) + رمز تحديث (30 يومًا) يُستبدل مع كل استخدام؛ إعادة استخدام رمز قديم تُلغي الجلسة كاملة.
- كل رمز مرتبط بجهاز؛ إلغاء الجهاز من المدير يوقفه فورًا.
- تغيير كلمة المرور يُبطل كل الجلسات السابقة.
- المستخدم المطالب بتغيير كلمة المرور لا يصل لأي عملية محمية قبل تغييرها.
- إعادة التعيين من مدير النظام تعطي كلمة مرور مؤقتة مع إجبار تغييرها.
- سجل تدقيق للدخول والفشل والخروج وتغيير/إعادة تعيين كلمة المرور وإلغاء الأجهزة.
- حساب المدير الأول يُنشأ من متغير بيئة فقط، ولا توجد كلمات مرور في الكود.

واجهات API:

| المسار | الوصف | الصلاحية |
|---|---|---|
| `POST /api/v1/auth/login` | الدخول | — |
| `POST /api/v1/auth/refresh` | تجديد الجلسة | — |
| `POST /api/v1/auth/logout` | الخروج | — |
| `GET /api/v1/auth/me` | المستخدم الحالي | دخول |

| `POST /api/v1/admin/devices/{id}/revoke` | إلغاء جهاز | `devices.manage` |
| `GET /health`, `GET /health/db` | فحص الحالة | — |

## 4. فروق مقصودة عن الصور — ✅ اعتمدها صاحب المشروع

1. **«الرقم السري» ← «كلمة المرور»** في حقل الدخول، لتتوافق مع رابط «نسيت كلمة المرور؟» ولأنها ليست أرقامًا فقط.
2. **أيقونة تسجيل الخروج** صغيرة أعلى الشاشة الرئيسية: الصورة لا تحتوي مكانًا للخروج، والمتطلبات تطلبه.
3. **الأيقونات** مركبة من مكتبة Material بأقرب شكل للصور (شاحنة + صناديق، أشخاص، بحث، تقرير + تحميل، جدول + رفع + ترس). أيقونة «الإدخال السريع» لا تستخدم شعار Excel التجاري. إن توفرت ملفات الأيقونات الأصلية (SVG/PNG) نستبدلها بها.
4. **الموجات** مرسومة برمجيًا لتتكيف مع كل المقاسات، فهي قريبة من الصور وليست نسخة مطابقة بالبكسل.

## 5. المشكلات المتبقية

1. **بناء APK محليًا غير ممكن في هذه البيئة**: موقع تحميل Android SDK (`dl.google.com`) محجوب في إعدادات الشبكة. الحلول:
   - بناء APK عبر GitHub Actions، وهو مُعد في CI ويرفع الملف كـ artifact.
   - أو إضافة `dl.google.com` للنطاقات المسموحة في إعدادات بيئة Claude.
2. **شاشة «تغيير كلمة المرور الإجباري»** غير منفذة في التطبيق لأنها بلا تصميم معتمد. السيرفر يفرض التغيير بالفعل. حتى اعتمادها يُنشأ المستخدمون الجدد من المدير بدون إجبار، أو يُستخدم مسار API مباشرة.
3. **تحديث صلاحيات دور** يسري على الجلسات المفتوحة خلال 15 دقيقة كحد أقصى (عمر رمز الدخول). إلغاء الجهاز وتغيير كلمة المرور يسريان فورًا.
4. قاعدة البيانات المحلية المشفرة (SQLite + Outbox) لم تُبن بعد؛ مخططة مع أول بيانات فعلية (العملاء والموردون) في المرحلة 3.
