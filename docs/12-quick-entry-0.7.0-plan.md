## قواعد العمل المعتمدة

- **إلزامي:** الاسم، موبايل مصري صحيح من 11 رقمًا، الخامة. **اختياري:** Grade، الشركة المصنعة، المنشأ.
- الإدخال السريع فقط؛ قواعد التسجيل اليدوي لا تتغير (الـ Grade يبقى إلزاميًا هناك).
- الـ Grade غير المطابق يُحفظ كنص «غير موثق» على ارتباط الخامة بالعميل/المورد (أعمدة إضافية اختيارية)،
  ويظهر ويُبحث فيه ويُصدَّر مميزًا عن Grades الكتالوج. لا تعديل صامت على الكتالوج المركزي.
- المطابقة فقط إذا كانت وحيدة ومؤكدة للخامة والشركة المصنعة الصحيحتين؛ الالتباس يحتاج مراجعة.
- تنظيف «بانتظار الاستكمال» استبعاد منطقي فقط؛ لا حذف فعلي، ولا استخدام «التراجع عن الدفعة» للتنظيف.

## المرحلة 3 — واجهات وأمان تنظيف «بانتظار الاستكمال» (منفذة — السيرفر فقط)

- [x] الاستبعاد الفردي `POST /pending/{id}/discard`: المستبعد سابقًا نتيجة ناجحة (`already_discarded`)، المكتمل `quick.closed`،
      والمرتبط ببطاقة أو الذي توجد بطاقة بمعرفه أو لم تنتهِ محاولة إنشائه `quick.protected` مع السبب؛ تدقيق `quick.discarded`.
- [x] استبعاد مجموعة `POST /pending/discard` (حتى 500): الصلاحية لكل صف، غير الظاهر «غير موجود» دون كشفه، المحمي يُتخطى بسببه،
      والمؤهل كله في حفظ واحد (معاملة واحدة) مع عدادات الدفعات والتدقيق `quick.discard_bulk`.
- [x] حذف الكل `POST /pending/discard-all`: معاينة بلا كتابة (المؤهل، المحمي بأسبابه، العداد المتوقع، رمز لقطة)، والتنفيذ بنفس
      الرمز فقط؛ أي تغيير بعد المعاينة `quick.snapshot_changed` دون أي استبعاد. فلتر اختياري للنوع أو الدفعة. تدقيق `quick.discard_all`.
- [x] الصلاحيات: صاحب الصف، أو `records.manage` ضمن ما يراه (الموردون لمن يرى الموردين فقط)؛ من يرى دون إدارة السجلات يظهر له
      صف غيره محميًا.
- [x] الاستبعاد منطقي: لا حذف لأي صف، ولا لمس للبطاقات أو الكتالوج؛ سجل التدقيق إضافة فقط. صفوف «بلا صلاحية» خارج القائمة والعداد.
- [x] تفعيل `cleanup_cases.json` (7 حالات أهلية + 7 حالات صلاحيات) في اختبارات السيرفر.
- ملاحظة: أزرار الحذف والتحديد المتعدد وحوار الخروج في الواجهة من المرحلة 4.
