# دليل تحديث سيرفر وتطبيق القادسية (تحديث تراكمي بدون إعادة تثبيت)

كل تحديث يُطبّق **فوق** النسخة الحالية: قاعدة البيانات، المرفقات، الحسابات، كلمات المرور،
ملف `.env` (المفاتيح وكلمات المرور)، عنوان السيرفر `192.168.1.12:5080` — كلها تبقى كما هي.

> **الإصدار الحالي 0.4.0** (السجل، الكتالوج، المواقع، المرفقات). خطوات التحديث نفسها:
> إذا كان سيرفرك ما زال على `ff9087b` فابدأ بـ«أولًا»، وإذا طبقت تحديث المرحلة الثالثة
> فيكفي «ثانيًا» (`bash update-trial.sh`). هذا الإصدار يضيف volume جديدًا للمرفقات
> (`qadisiyah-trial_attachments`) يُنشأ تلقائيًا بجوار قاعدة البيانات دون لمسها.

> لا يُطبَّق أي شيء على جهازك تلقائيًا. رفع التحديث على GitHub لا يغيّر السيرفر حتى تنفّذ الخطوات التالية بنفسك.

## ما لا يجب فعله أبدًا

| ممنوع | السبب |
|---|---|
| `docker compose down -v` | `-v` يحذف قاعدة البيانات بالكامل |
| `docker volume rm` / `docker volume prune` / `docker system prune --volumes` | يحذف قاعدة البيانات أو المرفقات |
| حذف أو استبدال `deploy/trial/.env` | يضيع كلمة مرور قاعدة البيانات ومفتاح الدخول |
| `bash init-env.sh` على السيرفر القائم | يُنشئ أسرارًا جديدة (السكربت يرفض ذلك إن وجد `.env`) |
| Docker Desktop ← Troubleshoot ← Clean / Purge data أو Reset to factory defaults | يحذف كل الـ volumes |
| حذف التطبيق من الهاتف أو «مسح البيانات» | يضيع عنوان السيرفر والجلسة المحفوظة على الهاتف |

الإيقاف الآمن دائمًا: `docker compose stop` أو `bash stop-trial.sh`.

## أولًا: التحديث الأول للمرحلة الثالثة (مرة واحدة فقط)

النسخة المثبتة عندك الآن (`ff9087b`) لا تحتوي سكربت التحديث، لذلك أول مرة تُنفّذ هذه
الخطوات يدويًا داخل Ubuntu (WSL). هذه الخطوات نفسها مُختبرة آليًا في GitHub Actions
(مهمة `Trial server update test`).

### 1) الفحص قبل أي تغيير

```bash
cd ~/qadisiyah/deploy/trial
git branch --show-current
git status --short
docker compose ps
```

المتوقع:
- الفرع: `claude/qadisiyah-analysis-planning-i2wgtx`
- `git status` يُظهر **فقط** ` M deploy/trial/init-env.sh` (إصلاحك المحلي) أو لا شيء.
- الحاويتان `postgres` و`api` تعملان.

إذا ظهر أي ملف آخر في `git status` أو فرع مختلف: **توقف** وأرسل لي الناتج.

### 2) نسخة احتياطية (إلزامية)

```bash
mkdir -p backups && chmod 700 backups
docker compose exec -T postgres pg_dump -U qadisiyah -d qadisiyah --format=custom > backups/before-phase3.dump
cp .env backups/env-before-phase3
cp init-env.sh backups/init-env.sh.local
ls -lh backups/
```

تأكد أن `before-phase3.dump` حجمه أكبر من صفر. (اختياري: انسخ مجلد `backups` إلى ويندوز أيضًا:
`cp -r backups /mnt/c/Users/<اسمك>/Documents/qadisiyah-backups`)

### 3) تنزيل التحديث وتطبيقه

```bash
git checkout -- init-env.sh
git pull --ff-only origin claude/qadisiyah-analysis-planning-i2wgtx
bash update-trial.sh
```

- السطر الأول يعيد `init-env.sh` لنسخة المستودع؛ نسختك محفوظة في `backups/init-env.sh.local`،
  والنسخة الجديدة من المستودع فيها الإصلاح (لا تستخدم `openssl`). أرسل لي محتوى نسختك
  لأتأكد أن إصلاحك مشمول.
- `update-trial.sh` يأخذ نسخة احتياطية ثانية، يعيد بناء السيرفر فقط، ويطبّق إضافات قاعدة البيانات
  (جداول جديدة فقط؛ لا حذف ولا تعديل لجداول موجودة).

النجاح يظهر هكذا:

```
تم التحديث بنجاح: ff9087b -> xxxxxxx
{"version":"0.3.0","schema":"..."}
السيرفر يعمل على: http://192.168.1.12:5080 — لا حاجة لإعادة تسجيل الدخول أو تغيير أي إعداد.
```

### 4) التحقق

```bash
curl http://192.168.1.12:5080/health
curl http://192.168.1.12:5080/api/v1/version
```

ثم ادخل من الهاتف بـ `admin` و**كلمة المرور التي اخترتها أنت** (لن يُطلب تغييرها مرة أخرى).

## ثانيًا: كل التحديثات بعد ذلك (أمر واحد)

```bash
cd ~/qadisiyah/deploy/trial
git status --short
bash update-trial.sh
```

السكربت:
1. يرفض العمل إذا وُجدت تعديلات محلية غير معروفة (ولا يغيّر شيئًا).
2. يأخذ نسخة احتياطية في `backups/` ويتوقف إن فشلت.
3. ينزّل التحديث (`git pull --ff-only`) ويعيد بناء حاوية `api` فقط.
4. لا يلمس `.env` ولا الـ volume ولا حساب المدير.
5. يتحقق أن السيرفر يعمل، ويطبع طريقة الرجوع إن لم يعمل.

## ثالثًا: الرجوع (Rollback) والاستعادة

**إذا لم يعمل السيرفر بعد التحديث** (البيانات لم تُحذف):

```bash
cd ~/qadisiyah/deploy/trial
git checkout $(cat backups/last-version-before-update)
docker compose up -d --build api
```

بعدها أرسل لي ناتج `docker compose logs --tail 100 api`. للعودة لمتابعة الفرع لاحقًا:
`git checkout claude/qadisiyah-analysis-planning-i2wgtx`.

**إذا لزم إرجاع البيانات لما قبل التحديث** (يُستبدل محتوى قاعدة البيانات بالنسخة المختارة):

```bash
ls backups/*.dump
bash restore-trial.sh backups/<اسم-الملف>.dump
```

السكربت يطلب كتابة `RESTORE` للتأكيد، ويأخذ نسخة احتياطية من الوضع الحالي قبل الاستعادة،
ويستعيد المرفقات أيضًا من ملف `attachments-<نفس التاريخ>.tar` المأخوذ مع نفس النسخة.

**نسخة احتياطية يدوية في أي وقت:** `bash backup-trial.sh` — تحفظ في `backups/`:
`qadisiyah-<التاريخ>.dump` (قاعدة البيانات)، `attachments-<التاريخ>.tar` (الشعارات والصور
وملفات TDS)، و`env-<التاريخ>` (الإعدادات). انسخ مجلد `backups` إلى ويندوز من وقت لآخر.

## رابعًا: تحديث تطبيق Android فوق القديم

- كل APK جديد له نفس الـ Application ID (`com.alqadisiyah.qadisiyah`) ونفس التوقيع،
  و Version Code أعلى من السابق (1000 + رقم تشغيل CI). يُثبّت فوق القديم مباشرة
  («تحديث»)، والبيانات المحفوظة على الهاتف تبقى. هذا مُختبر آليًا على محاكي Android
  (مهمة `Android in-place update test`).
- **استثناء لمرة واحدة فقط:** النسخة المثبتة على هاتفك الآن بُنيت قبل تثبيت مفتاح التوقيع،
  فسيرفض Android تثبيت الجديد فوقها («التطبيق غير مثبت» / تعارض الحزمة). في هذه المرة فقط:
  احذف التطبيق القديم من الهاتف ثم ثبّت الجديد، وأدخل عنوان السيرفر `http://192.168.1.12:5080`
  وسجّل الدخول. **لا يتأثر السيرفر ولا قاعدة البيانات ولا كلمة المرور** — ما يضيع هو فقط
  العنوان والجلسة المحفوظان على الهاتف. بعد ذلك كل تحديث يُثبّت فوق السابق بلا حذف.

**الإصدار 0.4.0:** يطلب التطبيق إذن الموقع **فقط** عند الضغط على «موقعي الحالي» عند إضافة
موقع، وإذن الكاميرا/الملفات عند إضافة صورة أو ملف. يمكن الرفض دون أن يتأثر باقي البرنامج.

## خامسًا: متى يُطلب تغيير كلمة المرور؟

فقط في: (1) أول دخول لحساب جديد، (2) بعد إعادة تعيين كلمة المرور من المدير،
(3) لأسباب أمنية يقررها المدير. **لا** يُطلب بعد أي تحديث. حساب `admin` يُنشأ فقط إذا كانت
قاعدة البيانات خالية تمامًا من المستخدمين، ولا يُعاد إنشاؤه أو تغيير كلمة مروره عند التحديث
(مُختبر في `SchemaUpgradeTests` وفي اختبار الترقية الآلي).

## إذا لم يكن المجلد نسخة git

إذا كان `~/qadisiyah` منسوخًا كملف ZIP وليس `git clone`، فـ`update-trial.sh` سيتوقف برسالة واضحة.
في هذه الحالة: نفّذ خطوة النسخة الاحتياطية (2) أعلاه، ثم أرسل لي ذلك لأعطيك خطوات تحويل
المجلد إلى نسخة git مع الإبقاء على `.env` وقاعدة البيانات كما هي.
